Finsight

A Python and Streamlit personal finance analytics application that transforms bank-statement data into clear insights on spending, income and savings behaviour.

4 Core financial metrics
01 / Situation

The problem

Personal bank-statement exports are often difficult to interpret directly. Transaction descriptions, categories and formatting vary between banks, making it harder to build a clear picture of spending behaviour, income and savings performance.

02 / Task

The objective

Build a lightweight analytics application that can accept bank-statement CSV files, normalize transactions into a common structure and convert the raw data into useful personal-finance metrics and visual insights.

03 / Action

What I developed

I built Finsight in Python using Streamlit and pandas. The application detects supported bank formats and delimiters, routes uploaded files through dedicated or generic parsers, and converts transactions into a standardized schema for analysis.

04 / Result

How insights are presented

The processed data is presented through an interactive dashboard showing key financial metrics, spending breakdowns, monthly trends and a transaction-level view.

05

Analytics Framework

From raw bank statement to financial insight

INPUT

Bank-statement CSV

Users upload exported transaction data from supported banks or another CSV format that can be interpreted by the generic parser.

PARSING

Format detection

Finsight automatically detects delimiters and attempts to identify the originating bank before routing the file to the relevant parser.

NORMALIZATION

Common transaction schema

Transactions from different sources are transformed into a consistent structure so downstream analytics can operate independently of the original bank format.

ANALYTICS

Financial metrics

The application calculates income, expenses, savings, savings rate, category-level spending and monthly financial trends.

06

Application Features

Core functionality

01

Bank format detection

Dedicated parsers are available for Revolut and Wise, with a generic fallback parser for unsupported CSV formats.

02

Transaction categorization

Rule-based logic categorizes transactions, while categories and keyword rules can be adjusted by the user.

03

Financial summary

Income, expenses, savings and savings rate provide an immediate overview of financial performance.

04

Spending analysis

Spending can be reviewed by category and across monthly time periods to make changes in financial behaviour easier to identify.

07

Engineering Decisions

Designing for different bank formats

PARSERS

Modular architecture

Bank-specific parsing is separated from the analytics layer, allowing new bank integrations to be added without redesigning the core application.

FALLBACK

Generic CSV support

When a bank is not recognized, the application attempts a best-effort interpretation using a generic parser and clearly indicates that the format was not detected.

PRIVACY

Local-first usage

Finsight is currently designed as a local development and portfolio application, avoiding the need to upload real bank data to a remote service.

TESTING

Synthetic sample data

Sample CSV files contain synthetic financial information so parser and dashboard functionality can be tested without exposing real transaction histories.
